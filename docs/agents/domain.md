# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root defines domain terminology.
- `docs/adr/` holds architectural decision records.

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being explored.

If these files do not exist, proceed silently. Domain modeling creates
them when terminology or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain modeling.

## Decisions

If a proposal contradicts an existing ADR, identify that ADR and
explain why the decision should be reconsidered.
